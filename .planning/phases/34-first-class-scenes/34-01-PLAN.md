<objective>
Promote scene definitions from the MC6 controller's `config.scenes` block to a top-level `scenes:` key in `rig.yaml`, and make `Rig.scenes` a real Pydantic field instead of a computed `@property` that aggregates from controller devices.

This is a hard cutover (D-01): `MC6Config.scenes` is removed entirely and `MC6Config` switches to `extra="forbid"` (D-04) so any stale `scenes:` under the controller config surfaces a clean error rather than being silently discarded. The loader parses the top-level `scenes:` block (D-03), fully hydrating `Scene` objects including `tempo`, and all fixtures and test builders are migrated to the new schema (D-02).

Purpose: Scenes become independent of whether a controller device exists, which unblocks controller-less apply (validated in plan 34-02) and makes the domain model honest about where scenes live.

Output: Updated `Rig` model, loader, `MC6Config`, migrated `sample_rig` fixture, and updated/added tests. The full suite stays green.
</objective>
